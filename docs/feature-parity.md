# Feature coverage and comparison

Publisher pages checked on **15–16 October 2026**. Luma coverage describes the independent **0.18.0 preview source**, including features whose production deployment or targeted live checks are still pending. A present button or passing replay is not evidence of complete protocol coverage. Luma has no paid feature tier.

## Public sharing and deployment state

The source includes the native sharing client, privacy-preserving report preparation, same-app Community section and hosted report/ranking implementation. The [public Luma Community service](https://luma-dps-community.uchihavayne.chatgpt.site) is available without an account. The 0.16 source adds viewing capabilities, CP bands and class statistics; production deployment and live checks of those new endpoints must be recorded separately from the older public-service checks below. An inaccessible service displays its state instead of reporting a successful upload or fabricated rank. Local clipboard, HTML, CSV and JSON sharing remains usable without the service.

The server checks payload shape, bounded values, arithmetic, scope and ranking context. A user-controlled summary is not an independently authenticated game log. Do not describe these records as verified world records. Public links are retained for 30 days and can be revoked earlier with the locally stored deletion key. Initial capacity is 5,000 reports / 100 MiB of report JSON, with 100 uploads per UTC day across the service and separate per-IP/read quotas; see the [exact initial limits](community-sharing.md#initial-service-limits). This is a bounded free community service, not an unlimited cloud archive.

The 0.16.0 source retains opt-in team rooms as an advanced alternative, separate from automatic game-party cooldowns: at most **12 participants**, **120 minutes** per room, **20 active rooms** and **20,000 successful sync requests per UTC day** across the service. Joining requires explicit consent to relay the participant's own name, class and cooldown observations. Native room keys remain in memory, server capabilities are stored as hashes, and room data is separate from public reports/rankings. Leaving stops synchronization; remote removal/host closure remains best effort when offline. These are Luma invitation rooms, not an authenticated game-party roster. Deployment and live multi-client behavior must be verified separately from local tests.

## Independent protocol evidence and asset provenance

The pinned MIT [AionDPS frame decoder](https://github.com/SkeeveAN/Aion-DPS-Meter/blob/72417dc72457844f514729fd2680fcbbd4423a93/Client/Aion2/Protocol/Aion2FrameDecoder.cs), [opcode configuration](https://github.com/SkeeveAN/Aion-DPS-Meter/blob/72417dc72457844f514729fd2680fcbbd4423a93/Client/assets/aion2/protocol/opcodes.json), [combat-frame findings](https://github.com/SkeeveAN/Aion-DPS-Meter/blob/72417dc72457844f514729fd2680fcbbd4423a93/docs/protocol/combat-frames.md) and [field-boss decoder](https://github.com/SkeeveAN/Aion-DPS-Meter/blob/72417dc72457844f514729fd2680fcbbd4423a93/Client/Aion2/Aion2FieldBosses.cs) document relevant routes and their validation boundaries. A route being documented does not prove all later regions and versions use it unchanged.

Pinned [ticket findings](https://github.com/SkeeveAN/Aion-DPS-Meter/blob/92806d72b1bb9cec4d092dc601d23447c7d67e29/docs/protocol/ticket-frames.md) and earlier [raw counter findings](https://github.com/SkeeveAN/Aion-DPS-Meter/blob/92806d72b1bb9cec4d092dc601d23447c7d67e29/docs/protocol/cooldown-frames.md), at revision `92806d72b1bb9cec4d092dc601d23447c7d67e29`, document ticket ID/absolute fields and the raw cooldown fallback's boundaries. Luma implements the supported structures independently and does not bundle an assumed raw conversion factor or an external ticket/skill catalog.

Direct cooldown/charge semantics are supported by Waffle's MIT [stream parser](https://github.com/Waffle-ens/waffle_meter/blob/cf885f1a9fac1758a14164286ce4c28ce0a01660/dotnet/src/WaffleMeter.Capture/StreamProcessor.cs), [field validation tests](https://github.com/Waffle-ens/waffle_meter/blob/cf885f1a9fac1758a14164286ce4c28ce0a01660/dotnet/tests/WaffleMeter.Capture.Tests/CooldownStartParsingTests.cs) and [cast grace tests](https://github.com/Waffle-ens/waffle_meter/blob/cf885f1a9fac1758a14164286ce4c28ce0a01660/dotnet/tests/WaffleMeter.Data.Tests/CooldownCastGraceTests.cs), pinned to `cf885f1a9fac1758a14164286ce4c28ce0a01660`. Luma uses independently written bounded decoders and synthetic fixtures. No external duration catalog, maximum charge assumption or shared-group mapping is used.

The newer pinned MIT [AionDPS frame decoder at `8459321`](https://github.com/SkeeveAN/Aion-DPS-Meter/blob/8459321bf3405fbf41a1d7776d26fbbd22671d39/Client/Aion2/Protocol/Aion2FrameDecoder.cs) supports the independently implemented periodic fields, local zone, equipped wing and five genus groups. Its typed `04 8D` appearance layout supplies acting combat ID, home server and name; the Waffle revision above documents character-snapshot variable prefixes, structural member profiles, spawn owner tags and the distinct exact-short `04 8D` death shape. Luma reads bounded fields rather than later guild text, requires agreement between repeated spawn-owner IDs, and does not promote a nearby record to self. Public wire examples and independently generated cases test these paths; private captured names/files are not source fixtures. See [received collection/amount semantics](received-character-collections.md) for amount bounds and remaining limits. No external character-name lookup runs as part of these local features.

No GPL meter implementation or external item/NPC/skill/icon catalog is bundled. The [skill-table provenance note](https://github.com/SkeeveAN/Aion-DPS-Meter/blob/72417dc72457844f514729fd2680fcbbd4423a93/Client/assets/aion2/skills/README.md) describes third-party origins; a repository-wide license does not establish redistribution rights to every embedded dataset. Runtime received names/IDs and independently created UI graphics remain separate from external catalogs.

The Windows RTT implementation follows Microsoft's [GetPerTcpConnectionEStats](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getpertcpconnectionestats) and [TCP_ESTATS_PATH_ROD_v0](https://learn.microsoft.com/en-us/windows/win32/api/tcpestats/ns-tcpestats-tcp_estats_path_rod_v0) contracts. RTT data is conditional on Windows support, permissions and fresh path samples.

## Release validation still required

Use the final executable for a synchronized solo Combat Analyzer test, an open-world run with nearby strangers and an actual party run. Verify actor names, self/party/observed totals, summon attribution, direct/periodic amounts and timing; actual explicit HoT fields must not become DPS or arm training. Include a mid-session start, missing roster, structural profiles, variable snapshot prefixes, verified spawn owners and actor despawn/reuse in name checks. Verify same-target Top 10 without a party, an unclassified shared PvE target, own rank beyond ten, separate party totals, boss-mode live-target continuity and HP current/max/gap freshness. Confirm unknown names are still disclosed and saved reports are not relabelled with guesses. Test the narrow NPC-effect exclusion against genuine player DoTs and paused capture. Compare Odyle regular/bonus values across login, consumption, gain and character switching. Test received CP/wing/genus values, pending ownership, capture-gap invalidation and immutable build snapshots. Test direct party cooldown durations, provisional casts, charge count/recharge, actual own zero, partial roster updates, changed party IDs and gaps in EU; expiry must not manufacture readiness. Validate actual zone changes, session grouping, received cast sequences/effect overlap and conditional HP projection. Test custom training cutoff, atomic import clearing, pet/stagger updates and RTT statistics/export. Verify optional rooms with consenting clients, hosted public/unlisted/keyed-private access/revocation, CP/class comparison bounds, LAN OBS on a second PC, shortcuts over the game and signed updater download/install/rollback. The 0.17 fullscreen implementation still needs HUD drag/resize, drawer closure, outside-HUD game clicks, global rescue, restored geometry and monitor/scaling checks with AION2 running. Real Cube trials must include faint audible stereo, camera turns, balanced/mono uncertainty and other-sound negatives; an offline reference match is not a live navigation result.

Version 3 of the existing public community service was deployed on **16 October 2026** from reviewed source; its new statistics route responded with the expected bounded, context-required schema. Private access is covered by local API/SQLite tests; a production keyed-private write/read check was not performed.

Unauthenticated public publication/retrieval/filtering/revocation was verified against the deployed endpoint on **15 October 2026**, including wrong-key rejection and removal from report/ranking results. These service checks and automated schema, privacy, replay and UI tests establish the cases tested; they do not establish full premium parity, worldwide data coverage or universal sound-detection accuracy.
