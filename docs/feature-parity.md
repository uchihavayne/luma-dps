# Feature coverage and comparison

Publisher feature pages rechecked on **21 October 2026**; the pet reference sources were reviewed on the same date. Luma coverage describes the independent **0.26.0 preview source**, including features whose production deployment or targeted live checks are still pending. A present button or passing replay is not evidence of complete protocol coverage. Luma has no paid feature tier. The default Clear interface keeps additional tools behind its overflow menu, with separately saved panel visibility.

## Follow-up review · 20 October 2026

The [A2Tools 2.0.70 release notes](https://github.com/taengu/A2Tools-DPS-Meter/releases/tag/v2.0.70) explicitly describe missing world-boss direct hits for players outside the local party. Its newer [2.0.73 notes](https://github.com/taengu/A2Tools-DPS-Meter/releases/tag/v2.0.73) also address focus/position behavior and event widgets. Transport loss of zero therefore does not establish a complete world-boss participant ranking. Luma labels its board as observed contributions and does not manufacture named rows or an exact global rank from missing hits. HP depletion alone is not safely attributable damage when the first HP point, healing or reset context is missing.

The current [A2Tools pet tracker description](https://a2tools.app/) and [PetTracker setup](https://github.com/0Fox2Give/PetTracker#readme) both obtain the initial collection at character login. Opening a meter after that transmission cannot reconstruct it passively. Luma 0.21.1 now automatically retains prior counters by validated character/home server and restores them as last received; new session gains remain visible and pinnable while the current baseline is unavailable. Repeated diagnostic exports or a manual sync button are not normal operation. A first unseen baseline, offline changes and unreceived actor names remain explicit limits.

The current [Aion2t Premium](https://aion2t.com/premium), [DaevaMeter](https://daevameter.online/features) and [Shugo.GG](https://shugo.gg/app) descriptions still identify additional collected datasets, spatial radar/replay and broader game-counter coverage. Those remain gaps in the independent Luma implementation, rather than completed features inferred from having a panel with the same name. These comparisons use published behavior and protocol descriptions; no external implementation has been incorporated by this follow-up.

## Personal-record review · 21 October 2026

[Questlog Desktop](https://questlog.gg/aion-2/en-nc/app) documents per-character boss-DPS personal bests and in-meter notices. [A2 Pro](https://a2prometer.com.br/) documents comparison against a previous best on the same boss. Luma 0.22.0 adds a distinct highest-single-PvE-hit record for server-identified self and confirmed game-party members, and a separate completed personal boss-DPS record. Neither is a global ranking or a percentile.

Single-hit records advance only on strictly greater received amounts, with summon attribution only when its owner is already confirmed. Unknown name/home server/class or unconfirmed party membership cannot produce a record. The first eligible value establishes a baseline; later improvements produce a short, silent, coalesced same-window notice. Notifications can be self-only, self/party, or off without disabling local recording. Up to 512 records persist privately in `personal-bests.json`; imported history never enters the live record queue.

Boss-DPS comparisons require a fully retained, gap-free completed single-boss personal encounter of at least ten seconds. Keys include character, home server, class, map, NPC template and reported maximum HP. The rate is compared with exact integer cross multiplication, not rounded display values or total damage. Received map/HP context is not independent verification of difficulty or a successful kill. Unknown comparison context stays in ordinary history without creating a boss-DPS record. The searchable same-window records section keeps hit damage and DPS units separate.

## Corrections prioritized in 0.21.0

The automated quality gate now runs the complete listed test suites before CI builds and records a public-source fingerprint; its own failure modes have regression coverage. See [quality gate](quality-gate.md). Pet collection ownership survives ordinary self death separately from live combat identity; real character/session changes reject old snapshots. Completed boss classifications stay with the saved encounter across live connection boundaries. These fixes establish the tested cases, not universal live accuracy.

- **Target visibility:** a Boss filter must not hide an otherwise valid observed Top 10. The live payload now includes bounded unfiltered board candidates and an encounter timestamp. A same-window selector exposes actual received shared targets without requiring a party or an identified boss. A remembered automatic focus starts only from an actual personal hit; it does not guess the largest target. If no personal target exists, exactly one fresh, active, same-encounter target with at least ten received contributors can open automatically as an observed shared fight. Multiple candidates require selection; crowd size never becomes a boss classification. A dedicated target DPS/personal contribution/rank card also works before a second contributor arrives.
- **Zero versus missing:** a separate unfiltered summary detects when Boss mode hides successfully decoded damage. The overlay explains that filter and offers Show All. Unknown identity/contribution and traffic with no decoded combat are explained separately; unknown rates remain unknown. A missing own board contribution is labelled as not received. These distinctions do not establish complete live protocol coverage.
- **Rate consistency:** paused time after a scope's capped end must not shrink that earlier scope or inflate its rate. Personal/party zero-duration observations stay zero, and missing rate fallbacks use the matching scope's total and clock. Native supplied rates remain authoritative. A target board deliberately uses one common target clock for all contributors.
- **Pet usability:** compact mode retains all saved pins, received points stay visible with an unknown level, and a real recent unpinned gain can be pinned directly. Twelve saved pins are independent of the additional automatic row. Unsupported thresholds, names, missed increments, world positions and catalog locations remain unknown.

These fixes address reproduced cases. They do not establish universal packet coverage, fully automatic boss identification, complete participant names or equivalence with every competing feature. A full current-client boss/NPC reference, spatial pet farming map, live nearby-monster radar, complete checklist and synchronized in-game comparison remain outstanding.

Deployment and live multi-client behavior must be verified separately from local tests.

Direct cooldown/charge semantics are supported by Waffle's MIT [stream parser](https://github.com/Waffle-ens/waffle_meter/blob/cf885f1a9fac1758a14164286ce4c28ce0a01660/dotnet/src/WaffleMeter.Capture/StreamProcessor.cs), [field validation tests](https://github.com/Waffle-ens/waffle_meter/blob/cf885f1a9fac1758a14164286ce4c28ce0a01660/dotnet/tests/WaffleMeter.Capture.Tests/CooldownStartParsingTests.cs) and [cast grace tests](https://github.com/Waffle-ens/waffle_meter/blob/cf885f1a9fac1758a14164286ce4c28ce0a01660/dotnet/tests/WaffleMeter.Data.Tests/CooldownCastGraceTests.cs), pinned to `cf885f1a9fac1758a14164286ce4c28ce0a01660`. Luma uses independently written bounded decoders and synthetic fixtures. No external duration catalog, maximum charge assumption or shared-group mapping is used.

The newer pinned MIT [AionDPS frame decoder at `8459321`](https://github.com/SkeeveAN/Aion-DPS-Meter/blob/8459321bf3405fbf41a1d7776d26fbbd22671d39/Client/Aion2/Protocol/Aion2FrameDecoder.cs) supports the independently implemented periodic fields, local zone, equipped wing and five genus groups. Its typed `04 8D` appearance layout supplies acting combat ID, home server and name; the Waffle revision above documents character-snapshot variable prefixes, structural member profiles, spawn owner tags and the distinct exact-short `04 8D` death shape. Luma reads bounded fields rather than later guild text, requires agreement between repeated spawn-owner IDs, and does not promote a nearby record to self. Public wire examples and independently generated cases test these paths; private captured names/files are not source fixtures. See [received collection/amount semantics](received-character-collections.md) for amount bounds and remaining limits. No external character-name lookup runs as part of these local features.

No GPL meter implementation is bundled. Version 0.25.0 adds the attributed NPC name facts, exact boss model ids and nine unchanged game class images documented in [reference data](reference-data.md); no external item catalog is bundled. Skill names come from a separately noticed table, see [skill names](reference-data.md#skill-names). The [skill-table provenance note](https://github.com/SkeeveAN/Aion-DPS-Meter/blob/72417dc72457844f514729fd2680fcbbd4423a93/Client/assets/aion2/skills/README.md) describes third-party origins; a repository-wide license does not establish redistribution rights to every embedded dataset. Runtime received names/IDs and independently created UI graphics remain separate from external catalogs.

The pet reference is a separate, attributed factual dataset: 207 pets and 495 monster/area records from a reviewed MIT snapshot, with primary ID/name cross-checks and per-pet source links. It includes no copied map tiles, game images or inferred world coordinates. Per-tier EU/NA requirements and the limits of static owned-effect references are documented in [pet sources](pet-sources.md). The catalog is not fetched at runtime, and opening a source/map link is an explicit user action.

The Windows RTT implementation follows Microsoft's [GetPerTcpConnectionEStats](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getpertcpconnectionestats) and [TCP_ESTATS_PATH_ROD_v0](https://learn.microsoft.com/en-us/windows/win32/api/tcpestats/ns-tcpestats-tcp_estats_path_rod_v0) contracts. RTT data is conditional on Windows support, permissions and fresh path samples.
