# Luma DPS

Luma is an independent Windows encounter meter for AION2 with Turkish and English interfaces. The 0.25.0 preview uses bundled game class images, resolves 12,587 NPC names and recognizes 559 boss model variants. The windowed Luma Clear roster automatically fits the players, with a one-line personal summary in the footer. Five players fit a 320×200 window without scrolling. Text stays at least 11px; up to twelve displayed players set a readable minimum window height when needed. Unbound sources without player identity remain in Analysis instead of crowding out named players. The overflow menu opens optional pet tracking, radar, event timers and the existing analysis, replay, records, community sharing and customization. Pet pins, collection counters and background capture continue when a panel is hidden. Complete protocol coverage, synchronized live DPS accuracy, extended pet continuity and real Cube guidance remain separate validation limits.

**Rekorlar:** Kendi ve oyunun doğruladığı takım üyelerinin en yüksek PvE tek vuruşu otomatik saklanır. 10K → 12K → 13K artışlarında kısa, sessiz bildirim görünür; eşit/düşük değerler bildirilmez. **Analiz → Rekorlar** bölümünde önceki değer ve artış yüzdesi bulunur. **Ayarlar → Savaş** bölümünden bildirimleri yalnız kendin için açabilir veya kapatabilirsin. Boss DPS, eksiksiz alınan ve en az 10 saniye süren tek boss denemelerini aynı karakter/sınıf/sunucu/harita/boss/bildirilen azami can bağlamında karşılaştırır; zorluk veya öldürme doğrulaması değildir. İlk kayıt başlangıç rekorudur. Veriler yalnız bu bilgisayarda tutulur ve uygulama kapanınca korunur.

## Hızlı başlangıç · Türkçe

1. Windows x64 taşınabilir ZIP dosyasını bir klasöre çıkar ve `Luma-DPS.exe` dosyasını aç. Windows yönetici onayını kabul et. Windows'un Packet Monitor API'si ve WebView2 sistemde bulunmalıdır; Luma Npcap veya ayrı bir yakalama sürücüsü kurmaz.
2. Otomatik karakter adı ve ekipman kaydı için Luma açıkken karaktere giriş yap. Oyuncu listesi varsayılan olarak **Yakındakiler** kapsamındadır: alınan oyuncu adları, toplam hasar ve saniyelik DPS birlikte görünür. Üst özet kişisel hasarını gösterir; yakındakiler buna eklenmez. Yapısal oyuncu profili adı, parti listesi gelmeden de okunabilir; bu kayıt tek başına parti üyeliği veya kendi karakterin olduğuna kanıt sayılmaz. Oyuncu olduğu doğrulanmamış sıfır hasarlı kaynaklar listeyi doldurmaz; doğrulanmış destek oyuncuları kalır. Gerçek adı gelmeyen hasar verenler uydurma adla gösterilmez; adın beklediği belirtilir. **Takım** filtresi alınan kadroyu kullanır. Kadro henüz gelmediyse liste bunu açıkça belirterek yakındakileri gösterir, takım toplamı bilinmiyor kalır. Kendi adın alınmazsa **Karakterim** bölümünde kendi satırını seç veya tam karakter adını kaydet.
3. **Etkinlik takvimi** bölümünden hazır EU etkinliklerini seç. Rift, Shugo ve diğer hazır saatlerde aralık veya başlangıç girmen gerekmez. Üst çubuktaki saati değiştirebilir veya kapatabilirsin; hatırlatıcıları ayrı ayrı açabilirsin.
4. **Ayarlar → Görünüm** bölümünde **Luma Clear** tasarımını ve koyu **Graphite** veya açık **Pearl** paletini seç. DPS renkleri düşükten yükseğe yeşil, sarı, turuncu ve kırmızıya ilerler; renkler görünen listedeki en yüksek DPS'ye göredir, sabit bir güç puanı değildir. Sınıf veya tema rengini de seçebilirsin. **Arka plan opaklığı** %0–100 arasında ayarlanabilir; yazı ve DPS bilgileri görünür kalır. Üstteki **Tam ekran** düğmesi ölçümleri ve oyuncu listesini ekranın tamamına yerleştirir; dar ekranda düzen tek sütuna geçer. **Pencere davranışı → Tam ekran düzeni** bölümünden ayrı **Saydam ekran üzerinde küçük HUD** seçeneğini de açabilirsin: başlıktan sürükle, köşeden boyutlandır; HUD dışındaki tıklamalar oyuna geçer. Varsayılan genel kısayol **Ctrl+Alt+Shift+F5** pencere görünümüne döndürür; Luma odaktayken **F11** de görünümü değiştirir. **Esc** önce açık ayar/analiz panelini kapatır, sonra tam ekrandan çıkar. Çıkışta normal pencere konumu ve boyutu geri yüklenir. Genel kısayol kaydı başarısızsa tam ekran açılmaz.
5. Hidden Cube sesi Luma açıkken arka planda otomatik dinlenir. Hazır ses referansı dahildir. Ses eşleştiğinde pusula aynı pencerede DPS listesinin yanında açılır; oyuncu listesi görünmeye devam eder. Ok yalnız güncel, tutarlı stereo kanıt sol veya sağ tarafı destekliyorsa görünür. Dengeli stereo, mono veya belirsiz yönde ok gösterilmez; kamerayı döndürerek karşılaştır. Zayıf referans sesi için daha uzun kanıt penceresi yaklaşık iki saniye gecikme ekleyebilir; ses eşleşse de yön bilinmiyor kalabilir. **Ayarlar → Hidden Cube** bölümünden dinlemeyi kapatabilir veya göstergeyi gizleyebilirsin. Dinlemeyi kapatma tercihin sonraki açılışlarda korunur. Stereo tarafı, kesin pusula açısı, metre veya harita konumu değildir; gerçek Cube yanında doğrulama bekleniyor. Ses ayrıca oyunun kendi Küp bildirimini de kullanır: oyun, yaklaşık 100 m içindeki Küp'ün konumunu gönderir; Luma mesafeyi, yüksekliği ve yürüdüğün yöne göre yönü gösterir. Konumun oyundan seyrek gelir (savaşta sık, yürürken birkaç saniyede bir); eski konum `~` ile işaretlenir.
6. **Analiz → Paylaşım ve sıralama** aynı uygulama penceresindedir. Sunucusuz paylaşım için karşılaşma metnini kopyalayabilir veya yerel rapor dışa aktarabilirsin. Ücretsiz [Luma Topluluk](https://luma-dps-community.uchihavayne.chatgpt.site) hizmeti herkese açıktır ve hesap gerektirmez. Uygulamada bitmiş bir kayıt seçip gizliliği inceleyerek açıkça bağlantı oluşturabilirsin; sıralamaya katılım ayrı ve isteğe bağlıdır. [Paylaşım kuralları](docs/community-sharing.md).
7. **Analiz → Planlayıcı** bölümündeki **Otomatik Odyle**, oyun bağlantısından alınan normal enerji, bonus ve toplamı gösterir. İlk liste için Luma açıkken karaktere giriş yap. Normal enerji sınırı yalnız alınabilen üyelik durumundan türetilir; bonus ayrıdır. Yenilenme tahmini alınan bakiyeye otomatik eklenmez. Elle girilen planlayıcı ayrı kalır. [Veri kapsamı](docs/resource-protocol.md).
8. **Analiz → Takım** kendi karakterinin ve doğrulanmış oyun partinin alınan cooldown’larını otomatik gösterir. Arkadaşlarının Luma kullanması, odaya katılması veya paylaşım açması gerekmez. Alınan süre, geri sayım, kullanım adedi ve dolum süresi ayrı gösterilir; sürenin bitmesi tek başına “hazır” sayılmaz. Sınıfa göre filtreleyebilirsin. İsteğe bağlı cihazlar arası paylaşım ayrı, açılır bölümdedir ve yalnız açık onaydan sonra başlar. [Takım cooldown’ları ve sınırlar](docs/team-cooldowns.md).
9. Kendi karakterinin yakın zamanda vurduğu hedef, alınan HP bilgisiyle aynı arayüzde görünür. Yalnız maksimum HP güncellemesi eski mevcut HP'yi güncel yapmaz; maksimum bilinmiyorsa yüzde uydurulmaz. Boss veya aynı PvE hedefine en az iki katkıcı için **Gözlenen Top 10** otomatik açılır; partide olman gerekmez. Yalnız o hedefe alınan hasar sayılır. İlk 10 dışında kalsan da kendi sıran ayrıca gösterilebilir; parti toplamı yalnız bilinen üyelikle hesaplanır. Boss filtresi, güncel kişisel hedefin ayrı görünümünü gizlemez. Bu liste resmî sunucu veya dünya sıralaması değildir; veri kaybı ve eksik isimler kapsamı sınırlar.
10. **Analiz → Pet rehberi** bölümünde 207 peti ara; tür, durum ve kalan ruha göre filtrele veya sırala. Referans 495 canavar/bölge kaydı ve 155 pet için kaynak harita bağlantısı içerir. En fazla on iki peti ana DPS listesinin üstüne sabitle; sonraki seviye veya en yüksek seviye hedefini seç. Normal EU/NA petlerinde kayıt için 5, ikinci seviye için o seviyede 25, üçüncü seviye için o seviyede 75 ruh gerekir; sayaç ömür boyu toplam değildir. Kalan miktar güncel alınan sayaçtan hesaplanır; eksik veya geçersiz sayaç sıfır sayılmaz. Süre tahmini yalnız geçerli gözlenen kazanım hızı varsa görünür. Harita bağlantısı kaynak sayfasını açar; oyun içi GPS, canlı konum veya otomatik rota değildir. [Pet verileri ve kaynakları](docs/pet-sources.md).

11. Başlıktaki dört kareli **Modüller** düğmesinden **Yalnız pet** görünümünü seçebilir veya DPS, pet, Cube, etkinlik, Odyle ve takım alanlarını ayrı ayrı gizleyip açabilirsin. Seçimin kaydedilir; modüller düğmesi her zaman görünür kalır. Aynı bölgede çıkan petleri rehberde bölge adıyla arayıp en fazla altısını sabitle. Her petin sonraki seviye sayacı, yüzdesi ve renkli çubuğu ayrıdır. Geçici kesintide son alınan değer korunur ve işaretlenir; eksik artışlar tahmin edilmez. Yeni geçerli tam sayaç geldiğinde canlı temel yeniden kurulur. DPS gizliyken pet listesi kalan pencere yüksekliğini kullanır; küçük pencerede tek listeden kaydırılır. Vurduğun yaratığın alınan NPC tür kimliği doğrulanmış pet kaydıyla eşleşirse, oyun yaratık adını göndermese de ana pencerede sabitleme düğmesi çıkar. Tür kimliği alınmamışsa yalnız tam alınan canavar adı eşleştirilir; bilinmeyen bir tür kimliği ad tahminiyle değiştirilmez. Bir yaratık birden fazla petle eşleşiyorsa her biri ayrı seçilir; bilinmeyen adlardan tahmin yapılmaz.

**Ayarlar → Kontroller → Yakalama uyumluluğu** bölümünde Windows sürümü/build’i, sistem ve uygulama mimarisi, System32 Packet Monitor DLL’si ve gerekli API işlevleri otomatik okunur. Yakalama hatası bildirimindeki **Tanı ↗** düğmesi de bu bölümü açar. Tanıyı JSON olarak kopyalayabilir veya yerel JSON dosyasına kaydedebilirsin. Bu inceleme yakalama başlatmaz, ek yönetici onayı istemez ve ağa bağlanmaz; uygulamanın normal başlatma/yakalama izinleri ayrıdır. API işlevlerinin bulunması canlı yakalamanın başlayabildiğini kanıtlamaz. Windows 10 desteğinin düzeltildiği veya alternatif bir yakalama yöntemi sağlandığı iddia edilmez.

Bağlantı bekleniyorsa durum yazısının ayrıntısını kontrol et. Oyuna girişten sonra Luma'yı açmak bazı kimlik kayıtlarını kaçırabilir. Tarayıcı önizlemesi canlı oyun verisi okumaz. Bu sürümde yeni senkronize oyun testi hâlâ bekleniyor; kapsam sınırlamaları aşağıda açıklanıyor.

**Analiz → Geçmiş** bölümünde oyuncu/boss/sınıf ara; tarih, kapsam, kategori, zorluk, etiket veya favoriye göre filtrele. En fazla 200 yerel kayıt ve yalnız bu cihazda saklanan not/favoriler kullanılabilir. İçe aktarılan raporları temizlemek, yakalanan karşılaşmaları korur; disk kaydı başarısızsa silme uygulanmaz. Aynı koşullardaki tam kişisel boss kayıtlarını karşılaştırabilir, HTML/CSV/JSON dışa aktarırken adları gizleyebilirsin.

## Quick start · English

Extract the Windows portable archive and open `Luma-DPS.exe`. Release builds request the standard Windows administrator approval needed for native capture. Windows' built-in Packet Monitor streaming API and WebView2 must already be present. Luma installs no Npcap or extra capture driver. Capture failures retain their actual operation and error code; a generic failure is not labelled as an unsupported Windows version.

**Settings → Controls → Capture compatibility** automatically reports the local Windows version/build, system and app architectures, System32 Packet Monitor DLL loading and required API exports. Capture error notices also offer a direct diagnostic shortcut. Copy the report as JSON or save it locally as JSON when troubleshooting. The inspection starts no capture, requests no additional UAC approval and makes no network request; normal app launch and capture permissions remain separate. Finding the exports does not establish that capture can initialize. This preview does not establish Windows 10 capture compatibility or add a fallback backend.

The independent application uses a separate settings directory and application identity. It closes only its own capture session. Completed fights, preferences and imported reports stay on this device unless you explicitly publish a selected encounter summary. There is no automatic upload or account requirement.

Start Luma before entering the character when testing automatic identity. Opening it after login may miss the self and build records; the meter then waits for received identity or an explicit fallback selection.

The recently attacked personal target has an integrated HP view and a separate observed contribution board. **Observed Top 10** opens automatically for a boss or a shared PvE target with at least two observed contributors, including a target whose boss classification is unknown. A party is not required. Only received damage to that target counts; your own rank remains available beyond the ten displayed rows, and party totals require known membership. Boss filtering does not remove the separate live personal-target view. This is a local observed comparison, not an official server-wide or world ranking. A missing maximum produces no invented percentage; a max-only update does not freshen an old current-HP reading.

Choose your display language and appearance in Settings. **Luma Clear** provides compact glass-style bars with dark **Graphite** or light **Pearl** colors. Relative-DPS colors progress from green through yellow and orange to red against the highest DPS in the displayed list; class/theme colors remain selectable. Background opacity ranges from 0% to 100% without hiding text or values.

The toolbar's **Fullscreen** button opens a dashboard that fills the viewport with larger measurements and a responsive roster. Narrow screens use a single-column layout. **Window behavior → Fullscreen layout** also offers a separate **Small HUD on a transparent screen** mode: drag its header and resize its corner; clicks outside that HUD reach the game. The default global shortcut **Ctrl+Alt+Shift+F5** returns to window mode. **F11** toggles the mode while Luma has keyboard focus; **Escape** closes an open settings/analysis drawer first, then exits fullscreen. Leaving fullscreen restores normal window geometry and preserves the saved HUD size. Fullscreen requires a successfully registered rescue shortcut. Actual pointer behavior over AION2, monitor changes and display scaling still require live checks.

Ready EU clocks need no entered interval or anchor; choose the compact header's event and enable reminders individually. Export the current encounter or history from Analysis as HTML, CSV or JSON, with optional anonymous names.

**Analysis → History** searches player/boss/class names and local notes across up to 200 local encounters. Apply scope, source, date, category, difficulty, tag or favorite filters. Notes and favorites stay on this device. Complete personal boss records under matching conditions can show local progress, best and median DPS. Clearing imported reports preserves captured encounters and commits the retained history before changing memory; a failed save does not delete records.

**Analysis → Planner → Automatic Odyle** shows received regular energy, bonus and total. Start Luma before character login to receive the initial list and authoritative self identity. Regular capacity is derived only from supported membership observations; bonus is separate. Refills are never silently added to the received balance, and manually entered planning remains separate. See [resource observations](docs/resource-protocol.md).

**Analysis → Team** automatically shows received cooldowns for your confirmed character and game party. Friends do not need Luma, an invitation or sharing enabled. Received duration, countdown, observed uses and charge recharge remain separate; an elapsed timer does not establish readiness. Filter by class without merging players of the same class. Optional sharing between devices is in a separate expandable section and starts only after explicit consent. See [team cooldowns, privacy and limits](docs/team-cooldowns.md).

**Analysis → Pet guide** includes 207 reference pets, 495 monster/area records and source map links for 155 pets. Search and filter the guide, choose a next-level or maximum-level goal, and pin up to twelve pets above the DPS roster. Ordinary EU/NA pets use per-tier requirements of 5 to register, then 25 and 75; the received counter is not a lifetime total. Remaining souls require a valid received level/baseline, and estimated time requires a valid observed gain rate. Unknown counters remain unknown. A map link opens a reference page, not an in-game GPS, live spawn tracker or automatic route. EU live counter/baseline validation remains pending. See [pet data and attribution](docs/pet-sources.md).

When your recently hit personal target has a received NPC template ID matching a verified catalog location, the main window offers direct pet pinning even without a received monster name. An exact received-name fallback is used only when the template ID is absent. Multiple matching pets are shown separately. Unknown or partial names are not guessed. With DPS hidden, the pet list fills the available height and scrolls inside smaller windows.

If Luma starts while you are already playing, leave it open for one return to character selection and re-entry so it can receive the initial pet list. A refresh reloads only data Luma has already received. Use **Clear filters** or **Show catalog details** to browse locations and pin pets while live counters are unavailable; missing entries do not mean that you own no pets.

Use the four-square **Modules** header control for **Pet only**, **All modules** or individual DPS/pets/Cube/events/Odyle/team visibility choices. Settings and the module recovery control remain available. Pins are preserved, and display choices do not silently stop packet capture or audio listening. Six pinned pets have independent numeric counters, colored current-tier bars and percentages; the maximum-level remaining amount is labelled separately. Transient loss retains received values as **Last received** with their original time and no ETA. Deltas after a broken baseline are not added to that counter; a fresh received absolute list restores it. Confirmed character or connection-generation changes clear old ownership.

**Analysis → Sharing and rankings** remains in the same app drawer. Copying an encounter text or exporting a local file works without a server. The free [Luma Community service](https://luma-dps-community.uchihavayne.chatgpt.site) is publicly available without an account. Online sharing is an explicit action with anonymous names by default and a separate ranking opt-in. See [sharing, privacy and eligibility](docs/community-sharing.md).

## How DPS is timed

DPS is damage divided by the time from the first hit to the last hit, per player or target window; the quiet time that ends an encounter (ten seconds without a hit, or thirty for a boss that is still alive) is not counted, and neither is healing that keeps an encounter open. A single hit has no span, so the one-second minimum divisor applies. The number shown while you fight is the number saved when the encounter closes: it does not fall during a pause between hits. Damage taken, summon attribution and pauses use the same clock, with pauses subtracted.

Effect entities such as a Cleric's auras are announced under their caster's name but without a class. When exactly one identified player carries that name (and the same home server when both are known), the entity's damage is credited to that player's row, in the analysis and the saved samples alike; with two candidates it stays a separate row. A player who is later identified with a class of their own is released. Summons and spell entities that are never announced or named are tied to a player by their damage records: the skills must come from one class (the class band of the skill ids), they must share a power scalar with the player (a summon inherits its owner's), the player must show at least three times as many distinct skills, and exactly one player may fit. The rule is recomputed continuously, so a binding that stops holding is released; anything that does not qualify stays in the unnamed-sources notice under the list. The rule follows the one the A2Tools meter documents and measured; it has not been checked against a live capture here.

**Combat detection** (Settings → Combat). By default an encounter ends after ten quiet seconds (five to three hundred, your choice); this is the "hits" source. The alternative "game" source follows the game's own combat state for you: the encounter stays open while the game counts you in combat, so a boss phase with no damage never splits it, and the chosen time is the wait after you leave combat. If the game has sent nothing yet, hits are used. The setting shows what the game last said ("you are in combat", "you are out of combat" or nothing received yet), which is how to check it on your own account: the frame layout (`21 8D`: entity, flags, state, optional berserk time) comes from how a second meter decodes it and has not been seen in a Luma capture here. DPS is timed from the first hit to the last hit either way.

A finished encounter, a boss kill above all, stays on screen until a new one actually deals damage to a target. Damage taken or a heal tick right after a kill is still measured and saved to history, but it does not replace the result you are looking at.

## Your character and measurement scope

The default player list is **Nearby**, independent of the header summary, which defaults to **Personal**. Received player names, total damage, per-second DPS and shares remain visible even when local identity is unresolved. The footer shows separate personal, party and nearby rates. Settings can change the player list, header/report scope and row values independently. Relative-DPS bar colors are the default; class colors or the theme accent remain available.

An explicit server self record identifies the current character automatically. No player's name or actor ID is hardcoded. If capture starts after login and misses that record, a saved name can bind to an exact, unique received player name, or the player can choose their observed row for the current session. An unresolved character shows an unavailable personal result rather than nearby players' damage.

Nearby typed `04 8D` appearance records and `33/44/45 36` snapshots recover received names, including supported variable-length prefixes and class suffixes. A structurally validated `00 92` profile identifies its named combat actor without waiting for the party roster; exact home-server/name matching still protects party membership. It cannot identify local self or create membership. Name-pending labels describe missing observations rather than inventing a character name; a server-confirmed character literally named `Unknown` keeps that name. These decoder fixes expand actual name coverage, but do not establish that every missing name is solved.

Complete supported summon spawns can repeat their owner as a varint and a tagged `u16`; Luma credits the owner only when those independent fields agree and identify another actor. The ambiguous bare `04 8D` prefix no longer establishes ownership; the exact short death record remains separate from longer appearance records. Actor respawn freezes earlier attribution before replacing the occupant's owner, name, class or health. Unconfirmed zero-damage sources are omitted from the participant view while uncertainty counters remain; real confirmed zero-DPS support players and received positive-damage contributors are retained. Saved history is not relabelled with guessed names, and private captures or captured player names are not distributed as fixtures.

**Party** uses received membership or an explicitly selected session roster. If membership is unresolved, the list can show received nearby players with an explicit notice; their presence does not establish a party, and the party total remains unavailable. A known party list filters to its members. **Nearby** (the observed scope in reports) includes the eligible actors visible in the received connection. A typed alias does not create party membership. Switching characters or reconnecting clears session selections; imported encounters cannot set live identity.

## Included

The nearby roster remains separate from the personal summary; received names and rates are not hidden by a personal header.

Complete comparable personal boss records provide local progress, best/median DPS and change from the previous attempt. Scoped HTML/CSV/JSON export, anonymous export, validated import and atomic clearing of imported reports remain available. Curves require complete retained samples.

- Automatic received Odyle regular/bonus/total energy, with a separately labelled membership-rule regular capacity when known. Bonus is not clamped, capture loss clears observations, and the manual planner does not overwrite game data.
- Conditional Windows TCP EStats RTT for existing eligible game IPv4 connections, without ICMP or extra game packets. Per-encounter analysis retains up to 600 timed samples with statistics, a chart and report export. The first read establishes a baseline; stale, unsupported, denied or unsampled paths show unavailable data. TCP RTT is not the game's application-response latency.
- Explicit per-second values such as `12.3K/sn` (Turkish) or `12.3K/s` (English). Rates keep the K unit above 1000 rather than switching to M; totals retain their own K/M units. Combined rows show total damage followed by the rate, for example `1.2M (12.3K/sn)`. The upper summary and player rows independently show DPS, total damage or both.
- Invalid packet timestamps fall back to receipt time so the encounter clock can advance. Old saved encounters with damage but zero duration keep their totals and display an unavailable DPS instead of an invented rate.
- Turkish/English UI, five original layouts including Luma Clear, dark Graphite/light Pearl and existing palettes, editable colors/fonts/density/columns, local images and appearance import/export. Player bars can use green-to-red relative DPS, received class or theme colors; background opacity covers 0–100%.
- Native movement/resizing, keyboard resize, pause/reset, focus-safe updates and movable settings/analysis panels. Fullscreen defaults to a responsive dashboard covering the screen; an optional transparent HUD retains its own drag/resize geometry. Both keep interactive drawers in the same window, require a global recovery shortcut and restore normal window geometry on exit. Compact-strip preferences do not shrink the dashboard. Closing a panel restores the compact window's position and size. The minimum normal overlay is 320 × 200; older shorter saved windows are expanded while preserving appearance preferences.
- Optional same-PC OBS browser source with per-session access token, explicit measurement scope and hidden names by default. It starts only when enabled for that session.
- Free clipboard encounter summaries and an integrated Community section: explicit selected-encounter link creation, anonymous names by default, copy/open/revoke, and optional filtered community rankings. The [public service](https://luma-dps-community.uchihavayne.chatgpt.site) is available without sign-in. No successful share or rank is invented while the service is unavailable.
- Background Hidden Cube sound detection with a built-in spectral reference and a compass that appears beside the DPS list only when a fresh match arrives. Smooth stereo steering, reference similarity, signal/noise readings and relative signal changes share the same overlay. Local WAV/M4A reference import accepts at most 8 MB and 30 seconds. Automatic game-only listening is on by default and can be disabled persistently; neither microphone capture nor automatic audio recording/upload is used.

## Hidden Cube sound locator

Listening starts automatically when Luma opens, including when upgrading settings that have no automatic-listening preference. It waits for AION2 if the game is not running. A fresh Cube match opens a compass beside the player list in the same overlay; damage rows and totals remain visible. The compass disappears when the match expires. There is no separate DPS/Cube page. The header's compass control opens the audio settings. Choose its compact or detailed layout there, or hide the indicator without stopping capture.

Turn off **Automatically listen for Cube audio in the background** or use **Stop listening** to stop capture. This choice is saved for later launches. Re-enable automatic listening in Settings when wanted. Stopping the damage meter is separate from the Cube listener.

Automatic listening always uses the AION2 process tree, including after an older setting selected system output. This uses Windows' built-in [application loopback API](https://learn.microsoft.com/en-us/samples/microsoft/windows-classic-samples/applicationloopbackaudio-sample/) and requires Windows build 20348 or later. System output can be selected explicitly for a manual listening session; it also includes sounds from other applications. Unsupported game capture does not switch to system output or a microphone. A device change retries the same selected source without broadening capture automatically.

The supplied sound's spectral reference is included; its original recording is not distributed. The detector compares several tone clusters against their local noise floors in each channel, allowing briefly masked frames. A longer evidence path supports faint-reference matching and may take about two seconds to respond. It can establish a sound match without sufficient fresh short-window evidence to show direction. The similarity percentage describes a signal match, not a probability or a calibrated sensitivity guarantee.

Direction uses fresh matched-sound stereo evidence rather than the overall volume of mixed audio. A side arrow shows left- or right-weighted sound; it does not show an absolute compass bearing. Balanced stereo, conflicting or uncertain evidence, mono and surround inputs show no steering arrow. The sound-match card may remain visible while direction is unavailable. Turning the camera provides another observation, without automatically resolving front/back ambiguity.

Signal strength and its change are relative audio cues. Music, similar chimes, game volume, headphone processing, occlusion and camera movement can affect them. The locator cannot calculate exact metres, absolute coordinates, elevation or an objective compass bearing from a mixed stereo recording. A centered signal alone does not establish that the Cube is in front of the player.

## Skill table, windows and map

**My skills** sit inside the main window, under the player list: the game's own skill icon, damage per second, share and total for every skill you used (up to twelve, then `+N` and a link to all of them). They appear by themselves once your own damage is received, in PvE and PvP alike, and the window's minimum height follows the table so no row is ever cut off. The arrow in its heading, or a click on the footer rate, collapses it to the heading; **Show my skills in the main window** in Settings hides it. The separate damage window is now only an extra: closed by default (a copy left open by an older version is closed once) and no layout opens it.

Separate windows you can open from the tools menu: **Health & frenzy**, **Target health** (the focus first, then bosses, each with a bar, percent and numbers; a creature's health is read from the moment it appears, and a value the game has not repeated lately is dimmed as the last one known), **Flight** (the flight points as a bar and, while they drain, the seconds left from how fast they run out), **Timers** (the event countdowns, open ones first), **Action bar** (your skills as tiles in fixed places with a shade that drains as each cooldown runs), **Opponent cooldowns** (what other players used, ally or opponent, from the cooldown the game announces with each skill, most recently active first), **Map** and the rest. **Map** draws the game's own map of the open world you are in (Poeta, Verteron, Eltnen, Ishalgen, Altgard, Morheim and the lower Abyss) with you in the middle, your heading from your last walk of at least 3 m, your party and the other players near; a click changes how many metres it shows. Dungeons, arenas and the upper Abyss have no picture and say so. The corners of each map come from the map definition of the public game database; they match the game's own coordinates by the same convention the rest of Luma uses, but the match was checked against the published definition, not against a live position.

**Alt+E** opens the **Overlay controls** window (also in the tools menu, and rebindable with the other shortcuts; it is the only shortcut that may use a single modifier): every separate window as a button, the scale, opacity, update rate and grid shared by all of them, the combat detection, and **Lock**, **Refresh** and **Done**. While it is open the windows are unlocked for editing: a dashed edge, a title bar with a refresh and a close button, a corner to pull. **Done** (or Alt+E again) locks them: they show only their content, lose the title bar and let every click through to the game. **Refresh** reloads every separate window and asks for the state again, for a window that is stuck or empty. **Ping** is a small pill of signal bars and the round-trip time. Every window is as tall as its content, so a row never hides when one is made smaller by hand: it grows back; the skill table drops its share and total columns before it cuts a skill name. Locking, Alt+E and the refresh were exercised in the Rust code's tests and in a browser preview, never on a running desktop or game; if Alt+E is already taken by another program the shortcut list in Settings says so.

**Ping**, **Flight** and the **Hidden Cube** are not windows but markers drawn straight on the screen, with no card and no title bar. The ping (signal bars and the milliseconds) starts in the bottom-right corner where the game draws its own; the flight time shows only while the flight points are running out, with the seconds left, a bar and the points; the Cube shows only while one is near. While **Overlay controls** is open (Alt+E) each of them shows a sample with a dashed edge so it can be dragged anywhere, for instance the Cube to the middle of the screen; **Done** locks them again and they let every click through. Luma starts locked.

The **Map** keeps your last known position on the map while the game sends the next one (it comes every few seconds, more rarely while walking), dimmed and with how long ago it was once it is old; it goes only when you leave the place or the position is half an hour old.

**Clean look** (Settings, on by default) shows the main window's buttons only while the pointer is over it and hides the notice cards that repeat the "!" status; the "!" and the tools menu still say it.

**Updates:** when the release feed has a newer, publisher-signed version, the main window asks "Do you want to download it?" and, once it is downloaded, "Install it now and restart?". **Later** keeps quiet about that version and step for a day. Luma asks the feed at start and every six hours while it stays open; Settings can switch that off. A version has to be published first (see RELEASING.md).

In Settings, **Window scale** (80 to 160 %), **Update rate** (250, 500 or 1000 ms) and **Snap windows to a grid when let go** apply to every separate window. The scale is a page zoom, the windows follow their content, and a window settles on the 20-pixel grid half a second after it stops moving. These were exercised in a browser preview and in the Rust code's tests, never on a running desktop or game.

## Hidden Cube game-data notice

Besides the sound, Luma reads the game's own Hidden Cube notices. The server announces a Cube once it is within about 100 m, with its world position, and says when someone starts opening it and when it is gone; a map load sends everything in range again. Luma shows the nearest Cube in the same compass dock, with or without the sound: planar distance in metres, whether it is above or below you, and its direction against the way you last walked (the compass top is your walking direction; right is positive under the game's Unreal-style axes). It also reports when someone else is opening it and how many more are in range.

The game does not send your own position continuously. It arrives with self-buff records, teleports, map loads and casts aimed at you: often in a fight, every few seconds to half a minute while just walking. A distance is calculated only from a position at most 30 seconds old and is marked `~` once it is more than 10 seconds old; direction needs a recent walk of at least 3 m and disappears when that walk is 30 seconds old. Without a recent position the notice only says that a Cube is in range.

### The Cube marker on screen

When a Cube is near and **Show a compass beside DPS when a Cube is detected** is on (the same switch as the dock), the game's own Hidden Cube picture (gold or red) appears straight on the screen with the distance in metres, an arrow turned the way to go, whether the Cube is above or below you, its compass wind, how long ago it appeared and, once the item list has arrived, how many keys you hold. It is not a window: it has no title bar, no frame and no background, and every click goes through it to the game. Nothing is drawn while no Cube is near. By default it sits top centre; **Place the Cube marker** in the Cube settings (Turkish: **Küp işaretinin yerini ayarla**) lets you drag it where you want until you press **Bitti**, and the place is remembered. **Only show it while I hold a Hidden Cube key** hides it while the item list says you hold none (it never hides while the key count is still unknown). The arrow turns against your last walk, like the dock's compass: it needs a recent walk of 3 m and a position at most 30 seconds old, and without them the marker shows the distance and the map wind only. Its place is checked in the real game only by you: the marker was exercised in a browser preview and in the Rust window code's tests, never against a running game.

Nineteen object templates are Cubes, in two looks: nine red (1200039, 1200040, 1200041, 1201503, 1201504, 1301199, 1301200, 1301244, 1301245) and ten gold (1200036, 1200037, 1200667, 1201502, 1201505, 1300081, 1300082, 1300754, 1301242, 1301243). 1200039 and 1200041 (Verteron) were confirmed from live captures by aion2-cube-radar; the rest come from how a second meter reads the same notices. The dock draws a red or a gold Cube, says how long ago the server created it (from the Cube's own creation time against the server clock in the map frames) and whether it appeared while you were looking, keeps an opened Cube listed for eight seconds marked as opened, and gives its direction on the map (north is world −y, east is world +x) next to the direction against your last walk. Opening any other object with a Hidden Cube Key still teaches Luma its template, saved in `cube-templates.json` in the app data folder. The frame layouts are documented from captures by [aion2-cube-radar](https://github.com/dr89mh/aion2-cube-radar) (GPL-3.0); Luma's decoder is an independent implementation of those facts.

## PvP

The chip **PvP 3/1** (kills/deaths this session) appears in the tools row once you have a kill or a death; click it for the three big numbers and your last death. The game announces every death with the victim, the skill and the killer, a player with name and home server, a monster with its model. A kill counts when you, or a summon of yours, killed another player; a death counts when it is you. When you die the panel opens by itself for twenty seconds with who killed you, with what, how much damage you took in the ten seconds before and the three skills that did it. The meter's reset button clears the session. Assists need the character id of the game's score packet and are not read yet, so that number shows a dash.

The input level is separate from the matched Cube signal. A quiet-input notice means the selected stream is arriving without meaningful audio; check the game's sound and background-mute settings while keeping it audible. No arrow is retained after listening stops, an error, an audio gap or an expired match. A Windows timestamp-uncertainty flag no longer clears valid detector history; an actual sample discontinuity still does.

You can replace the reference with a clean local WAV/M4A recording while listening is stopped. [Windows Media Foundation](https://learn.microsoft.com/en-us/windows/win32/api/mfreadwrite/nf-mfreadwrite-mfcreatesourcereaderfrombytestream) decodes it in memory; only a bounded spectral template is retained on this device. Silence and non-distinctive references are rejected. Stop listening before changing its source, sensitivity or reference.

Offline reference-mixture checks exercise faint sound evidence and stereo consistency; they do not establish a detection threshold, false-positive rate or accuracy in every game scene. Strong masking can still prevent a match. Earlier bounded AION2-only stereo captures opened and stopped on Windows, but effectively silent input did not verify a Cube encounter. Live Cube recognition and steering still require audible in-game comparisons, camera turns and other-sound negatives.

## My skills

Click your rate in the footer (**Sen 8.25K/sn 40.41K**) to open your skills over the list: the five that did the most damage, each with its damage per second over your own clock, its share of your damage and its total, and how many more there are. It follows the live numbers, closes with the × button, a second click on the footer or Escape, and **All skills** opens the full breakdown in the analysis. Skill names come from the bundled English table; an unknown skill shows its id.

## Monster casts

The warning strip above the list now also shows the monster casts about to land, up to three at once, soonest first with the ones aimed at you ahead of the rest: caster, skill (by name when known, otherwise by id) and the time left of the received windup. A cast aimed at you keeps the warning colour and, with sound on, the beep; the others are shown plainly and can be switched off under **Settings → Alerts**. Only hostile monsters count: players, party members' casts, summons and pets never appear. The countdown follows the received windup duration; it does not predict when damage lands, and Luma does not mark a cast area-wide because it does not track a skill's spread.

A cast aimed at you is marked **LETHAL** only on evidence Luma has seen: that same skill has already hit you for at least the health you have now (your health comes from the game's point updates, and the skill's strongest hit on you is remembered for the session). A skill that has never hit you is never called lethal, and a cast loses the mark as soon as you are healed above what it did. **Boss frenzy** is the countdown chip beside the other tools ("Öfke 1:05", orange in the last thirty seconds): the game announces when a boss enrages on the server's clock, and Luma shows it once it has also seen the server clock in a map frame, so it can place that time on your computer's clock; the soonest one is shown. **Settings → Combat → Show my health** adds an HP chip with your health and, when the game reported a maximum, the percentage; below thirty percent it turns red. The maximum is never guessed from the highest health seen.

## Separate windows

**Tools → Separate windows** opens PvP, health with the boss frenzy and monster casts, the Hidden Cube, the party and its room, tickets, currencies, a session tracker, your skill cooldowns and the effects on you as small windows of their own, each opened and closed on its own. Every window is as tall as its rows, so none has to be resized to see everything, and none takes focus from the game. A window is a glass card with a title bar to drag, a corner to resize and a close button; it stays above the game, comes back where you left it (clamped onto a screen that still exists, so an unplugged monitor never strands it) and is taken down with the meter. A window only reads: it asks for the same game state as the meter, never saves a setting, and keeps nothing except its place (`overlays.json` in the app data folder). The meter itself is unchanged, so you can keep everything in one window, move only what you want out, or both. **Damage** is the window that needs no opening: it is there from the first start, shows itself when a fight begins and for fifteen seconds after it, and hides again. It ranks every skill you used, each with the game's icon, its damage per second, its share and its total, under your own damage per second and the time of the fight. Closing it is remembered; **Tools → Separate windows → Damage** brings it back.

**Party** is the party finder room when you are in one: every member with class icon, name and home server, gear score, combat power and whether they are ready (the leader counts as ready), the room's average combat power, and, when the party list also gives their health, a thin health bar under the row. Someone joining the room appears at once. Without a room it lists the party members with health bars (the game pushes a member's health as it changes, so a member at full health simply shows full). **Tickets** is a card for Odyle (count, bonus, the most it holds from your membership, its refill rule and the next refill when the game says it), tiles for the tickets that count uses (name, count, bonus and the most each holds) and lines for the ones that hold hours, such as the Lower, Middle and Upper Abyss. **Currencies** lists what you carry that the game counts as money (the items numbered 930100xxx) and Odyle. **Tracker** counts the monsters you hit that then died (by their model name when Luma knows it), what you looted (items that grew by a drop, a reward, a quest or gathering, never by moving between bags) and what gathering gave; the meter's reset button clears it. Skills, effects, tickets and currencies carry the game's own icons, bundled with Luma (`ui/assets/icons`, refreshed with `tools/fetch_icons.py`; see docs/reference-data.md). The game sends tickets, items and servers by number only, so their names, the most each ticket holds and how it refills come from a catalog bundled with Luma (which also names the effects, `ui/game-catalog.mjs`, refreshed with `tools/fetch_catalog.py`; see docs/reference-data.md); Luma never goes online for them. Under **Settings → Combat** you choose which tickets the Tickets window shows (Odyle is always there, and the usual ones are shown until you choose), and you can name a number the catalog does not know; a name you type always wins. **Skills** shows the cooldowns the game has told Luma about for your own skills, cooling ones first. **Effects** lists the buffs and debuffs on you that the game shows, with the time left: what takes control away (stun, knockdown, airborne, fear, paralysis, sleep) first and in red, then what harms, then what helps. Whenever one of those control effects is on you, the health window shows a red **loss of control** banner with its name and time, and the meter's tools row a red chip with a beep when sound is on; you are out of control until the last of them ends. The health window also shows your ping when the game connection has a fresh sample. **Tools → Layout** opens a ready-made set of windows and closes the rest: *Essentials* (health, frenzy and the control warning), *Raid* (that plus skills and effects), *PvP* (PvP, skills, effects and health) and *Minimal* (none). **Assists** in the PvP window come from the game's battle score once the game has listed you in a party, because that list is where your character id is read; solo, the number stays a dash. The room, party, score, gathering and item layouts come from how a second meter decodes them (the room's member record also matches the layout Luma's own party updates were built from) and are checked here only against frames built to those layouts, bit-shared booleans included, not against a capture. A map tracker is not built: it needs the game's map images and a coordinate calibration that Luma does not have; the Radar in the tools menu shows nearby actors in metres.

This is the desktop app's feature; it cannot be tried in the browser preview, and the window handling (opening, dragging, resizing, restoring) has been compiled and unit-tested for its place bookkeeping but not run on a real desktop here, so report anything that misbehaves.

## Data capture

**Settings → Controls → Data capture** saves the last two minutes of raw received game frames to `captures` in the app data folder, with a short note you type (for example `pvp` or `gathering`). It exists so a feature that needs real traffic, such as a PvP view, gathering-node names or auction data, can be built from it. The frames are kept only in memory (at most 40,000 frames or 12 MiB) until you press the button; the file can contain player names and chat, is never uploaded, and the newest five are kept.

## Coverage

The meter measures what the game connection supplies. A nearby player may not appear if the server does not send their events. Receiving traffic alone does not establish an encounter or local identity.

Boss classification and unfamiliar skill/target labels still need validated mappings or user selection. Manual boss marks apply only to the live session; actor IDs from old settings are discarded. Map slot IDs are not guessed into boss names. A passed map deadline waits for a fresh server report rather than claiming the boss spawned. Ready event clocks use published community schedules and public calendar subscriptions; they do not establish live availability or NCSOFT confirmation. Nahma remains a provisional community preset. See [event sources and clock rules](docs/events-sources.md).

Live healing classification remains unsupported where the wire form is ambiguous. Player/pet-to-player amounts are retained as unclassified and excluded from damage/HPS until that distinction is verified; PvP statistics are therefore not yet supported. Unsupported HPS is unavailable; saved game reports can provide their own healing totals. Verified NPC damage to a player's body is shown separately with coverage information. Odyle energy is read automatically from supported Contents Ticket records; this is not a complete item inventory or an automatic refill projection. Public sharing/rankings are available through [Luma Community](https://luma-dps-community.uchihavayne.chatgpt.site). Community submissions and local history are not a verified world ranking or an all-player percentile.

Gear observations are partial and do not bundle an item catalog. A separately noticed English skill-name table labels skills; see [reference data](docs/reference-data.md#skill-names). The nine bundled game class images and NPC facts have separate provenance and notices in [reference data](docs/reference-data.md). Equipment ownership requires confirmed server self identity; a matching inspection name or manual row selection is insufficient. Starting midway through a session can miss login lists.

TCP retransmissions are removed; bounded frame recovery and capture-loss reporting protect totals. Loss invalidates partial records and marks measurements. The native backend currently supports incoming IPv4 TCP for the allowed AION2 executables. IPv6, encrypted game traffic, unsupported executables and oversized/incomplete snapshots are reported limitations. See [capture details](src-tauri/NATIVE_CAPTURE.md), [protocol coverage](docs/observed-character-and-bosses.md) and [feature comparison](docs/feature-parity.md).

Browser preview has no live connection. `?demo=1` shows fixed sample records and an explicit DEMO label.

## Sharing and community rankings

Choose a finished current encounter or a saved record in **Analysis → Sharing and rankings**. Online publication requires an explicit consent control; background measuring never uploads encounters. Anonymous is the default. If you choose to expose your name, other players still use anonymous labels. Raw packets, audio, private notes, unrelated encounters and original actor IDs are excluded from public summaries. A link can be revoked from the app and expires after 30 days; local encounters remain available independently.

Ranking participation is separate from sharing. Ranked results require confirmed own identity/class, complete live capture, at least 10 seconds of personal measurement, and exactly one named boss target matching the supplied boss context. Region/server/class/boss/difficulty filters describe opted-in community records only. The service checks structured values and arithmetic; a client-submitted summary is not an authenticated game record. Mixed-target, imported, short, incomplete and manually identified encounters do not qualify for rankings even when their valid summaries can be shared.

The [public Luma Community service](https://luma-dps-community.uchihavayne.chatgpt.site) is available without an account. Unauthenticated publication, report retrieval, filtered rankings and revocation were verified on 15 October 2026. An unavailable or unconfigured endpoint leaves local measuring, clipboard summaries and HTML/CSV/JSON exports working. Free online service capacity and rate limits are bounded; see [community sharing](docs/community-sharing.md) for exact initial quotas, privacy, recovery and retention, and [feature comparison](docs/feature-parity.md) for unsupported features.

## Build and test

Run from this source directory on Windows with the MSVC build tools, Rust 1.95.0, Node.js 24 and Python 3.11 or newer. These are development tools; players only need the portable application and the Windows components described above.

```powershell
cargo test --manifest-path engine/Cargo.toml --locked
cargo test --manifest-path src-tauri/Cargo.toml --locked
node --test ui/tests/*.test.mjs
python -m unittest discover -s tools/tests -p "test_*.py"
python tools/package.py --check-source
cargo build --release --manifest-path src-tauri/Cargo.toml --locked
python tools/package.py
```

Use `--offline` for Cargo after the dependencies are cached. The frontend has no npm runtime dependency; the desktop build embeds it directly. Cargo lockfiles pin dependency versions; the workflow selects the Rust toolchain explicitly. Packaging compares configuration, Cargo/lockfile versions and the executable's file/product resources, rejects an executable older than its build inputs, verifies x64 and the administrator manifest, and includes public source hashes and dependency notices. Captures, local settings, exported reports and build caches are excluded. Source and portable archives include the documentation needed by their README links.

For a local browser preview, run `node ui/serve.mjs`, then open `http://127.0.0.1:7335/`. Add `?demo=1` to see clearly labelled sample data. See [UI behavior and development](ui/README.md).

The Windows GitHub Actions workflow runs tests and builds reviewable packages. It creates build artifacts; publishing a GitHub release is separate.

The calendar client requests only three fixed public HTTPS subscription URLs. It sends no character names, damage records or accounts. Refreshes happen at startup when needed, daily thereafter, or on explicit refresh. Invalid responses preserve the last valid schedule; certificate verification remains enabled.
